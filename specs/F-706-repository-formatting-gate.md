# F-706 · Repository Formatting Gate

**Status:** APPROVED (2026-08-29, product-owner approval recorded in issue #302) · **Reviewer/approver:** product owner · **Owner:** product owner · see `docs/BASELINE.md`.
**Phase:** 0, Platform & Rules Administration · **Issue:** [#302](https://github.com/jzeng151/pop-engine/issues/302)

## Purpose and user outcome

Contributors get the same repository-wide formatting result locally and in pull-request CI. Formatting drift fails before the slower validation steps run.

## Scope

In scope:

- Run the existing `pnpm format:check` command in CI after the frozen-lockfile install.
- Exclude three files or file sets that are not authored through Prettier: immutable captured HTML, pnpm's generated lockfile, and the archived or proposed full rules draft.
- Normalize `LICENSING.md` with the repository's existing Prettier configuration.

Non-goals:

- No new formatter, dependency, configuration file, or auto-formatting CI job.
- No application, API, schema, migration, engine, ruleset, fixture, or regulatory-content change.
- No broad directory exclusion and no exemption for ordinary authored source or documentation.

## Dependencies and baseline

This feature uses the existing root `format:check` package script, installed Prettier version, pnpm lockfile, and Node 22 CI job. It has no feature dependency and does not change any shared contract.

## Inputs, outputs, validation, and errors

The input is the checked-out repository after `pnpm install --frozen-lockfile`. The output is a passing or failing `prettier --check .` process. A formatting mismatch returns a nonzero status and stops the CI job. The check does not rewrite files.

`.prettierignore` contains exactly these additions:

- `docs/proposals/advisory-144-refetch-2026-07-28/*.page.html`
- `pnpm-lock.yaml`
- `rules/proposals/nyc-rules.v2-full-draft.json`

The first path is an immutable upstream capture. The second is generated by pnpm. The third is not an approved implementation input. All other tracked authored files remain in the check.

## UI, accessibility, privacy, and security

There is no user interface, persisted state, provider, job, or data flow. The feature reads repository files only. It does not inspect or publish secrets or regulatory facts.

## Acceptance criteria

1. **F706-AC-01:** `pnpm format:check` succeeds on the approved repository state and reports a nonzero exit status when an included file does not match the existing Prettier configuration.
2. **F706-AC-02:** The pull-request and `main` CI job runs `pnpm format:check` immediately after `pnpm install --frozen-lockfile` and before baseline, migration, typecheck, lint, coverage, and build checks.
3. **F706-AC-03:** The formatting check excludes only the three additions listed above. It does not exclude a broader directory or file class.
4. **F706-AC-04:** `LICENSING.md` passes the formatter with its licensing statements, names, URLs, and license classifications unchanged.
5. **F706-AC-05:** Baseline validation, database migration, typecheck, lint, coverage, and build remain green after the formatting gate is added.

## Fixtures and verification

There are no regulatory fixtures. `pnpm format:check` verifies F706-AC-01 and F706-AC-04. The CI workflow order verifies F706-AC-02. Direct inspection of `.prettierignore` verifies F706-AC-03. The existing CI commands verify F706-AC-05.

## Allowed file footprint

`.github/workflows/ci.yml`, `.prettierignore`, `LICENSING.md`, this spec, and the matching `docs/ROADMAP.md` and `docs/BASELINE.md` records. No other file is authorized.

## Rollout and fallback

The gate applies to pull requests and pushes to `main` when the workflow lands. Reverting the CI step removes CI enforcement. Reverting the three `.prettierignore` entries restores the prior local check coverage.
